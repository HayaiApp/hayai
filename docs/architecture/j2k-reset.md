# Hayai on TachiyomiJ2K

Hayai is rooted directly at TachiyomiJ2K commit `8df100d6e616851e329b274964c726dcef0556b6`. The previous mixed Hayai/Rokku tree is preserved at `legacy/hayai-pre-j2k`; none of its Kotlin code is part of the current baseline.

## Boundaries

J2K owns manga, chapters, history, categories, tracking, downloads, image reading, and normal extension loading. New behavior lives under `dev.ahmedmohamed.hayai`:

- `adult`: adult classification and the global/tri-state library policy.
- `source`: typed source capabilities and enhanced-source families.
- `novel`: the text-source contract, document renderers, and adapters hosted by J2K's reader.
- `migration`: read-only legacy import and typed Hayai side tables.
- `backup`: versioned serialization and stable-ID remapping for Hayai-owned side data.
- `preferences`: stable Hayai and TachiyomiSY-compatible preference keys.
- `recents`: presentation-only source visibility shared by History, Updates, and mixed views.

`tools/verify-upstream-boundary.ps1` rejects unreviewed Kotlin edits outside this namespace. `App.kt`, `MainActivity.kt`, and the J2K image `ReaderActivity.kt` are protected explicitly.

`AppModule` delegates process classification to `HayaiProcessPolicy` before scheduling asynchronous database, source, download, and WorkManager-backed initialization. The main process retains the normal startup path; the isolated crash-handler process imports only the synchronous dependencies its activity needs. This prevents a primary failure from being hidden by a second WorkManager initialization crash without changing `App.kt`.

`ReaderActivity` is an approved protected seam for two documented adapters. `ReaderLauncher` owns a namespaced initial-image-page extra so source previews enter J2K at the selected page. For proven novel sources, `ReaderActivity` hosts a Hayai `BaseViewer` and action attachment while retaining J2K's lifecycle, chrome, chapter sheet, navigation, and state models; `ReaderViewModel` and `ChapterLoader` contain the matching typed progress and loader branches. Image sources retain their original loaders, viewers, page semantics, and double-page behavior.

The J2K backup pipeline is an intentional narrow adapter seam: `Backup` owns one optional high-numbered Hayai field, `BackupCreator` fills it, and `BackupRestorer` applies it only after J2K has restored manga and chapters. All payload validation, serialization models, stable identity mapping, and database behavior remain Hayai-owned. This preserves old-backup compatibility and avoids teaching J2K models about Hayai tables.

`ExtensionLoader` is also an intentional adapter seam. Standard `tachiyomi.extension` packages retain J2K's exact label, version-name library decoding, signature trust, NSFW metadata, class-name resolution, private-extension, and source-construction path. Only packages declaring Tsundoku's `tachiyomi.novelextension` feature enter Hayai's pure `NovelExtensionManifest` adapter, which normalizes Android float metadata before compatibility checks and accepts the audited Tsundoku class namespace. A small `eu.kanade.tachiyomi.source.NovelSource` compatibility shim retains the exact legacy binary name and recognizes both the current virtual property and older marker implementations. This adds novel APK support without creating a second extension manager or changing manga APK behavior.

Extension discovery uses one Hayai-owned `ContentKind` policy for browse, search, reader routing, and migration. The J2K Extensions sheet retains its Manga and Migration behavior and adds a peer Novels tab using the same cards, language groups, installed sorting, search, progress, install, update, settings, trust, and uninstall interactions. `ManagedExtensionProjector` unions novel APK state and LNReader JavaScript plugin state into that Novels tab with namespaced `apk:` and `js:` identities; manga APKs remain in Manga, while a mixed APK can appear in both tabs. Installation, update, and health are orthogonal, so an installed plugin remains manageable while its runtime is unhealthy or its repository is offline. Language and adult-source filters apply only to remote available entries; installed, untrusted, and load-failed packages remain manageable. J2K continues to own APK loading, signature trust, package installation, source registration, and update semantics. `NovelPluginManager` owns only JavaScript repository trust, checksums, signing keys, QuickJS warm-up, atomic storage, and semantic versions.

The package-installer activity retains J2K's downloaded APK, session, signature, and result path. On Android 8 and newer it now obtains the per-app unknown-source permission before creating the install session, then resumes the same APK when the settings activity returns. Denial reports an installation error through J2K's existing extension flow. This prevents a doomed session from leaving the shared Manga/Novels card stuck on `Installing` without introducing a Hayai installer.

APK repository URLs remain in J2K's single `extensionRepos` preference. Fresh installations start with the user-selected Keiyoushi and Cursed Manga protobuf indexes; both remain Manga repositories, with adult visibility still controlled by J2K's source filter. Hayai stores novel membership tags only for backup, restore, and redirect compatibility. The APK repository section lists every global APK index, regardless of content kind; adding, removing, or replacing a URL updates the global set and Hayai tags together. Browse and Browse settings expose explicit APK-index and LNReader JavaScript destinations, but both destinations reuse J2K's `RepoController`, inline create row, adapter, holder, validation spinner, edit, delete, and undo behavior. `RepoPresenter` switches only the persistence and validation backend. A JavaScript repository's display name is derived from its URL after its index validates, so adding either repository format requires exactly one URL field and no separate form. Fresh installations seed the supplied LNReader v3 index once; removing it is durable and does not recreate it on restart.

LNReader-compatible JavaScript sources use a separate Hayai-owned trust boundary. `AppModule` registers one manager. `SourceManager` merges the manager's source flow with J2K's authoritative APK source flow and rejects source-ID collisions. Repository documents and plugin downloads are bounded. `NovelPluginRepositoryDocument` normalizes current root arrays and legacy `plugins` or `sources` envelopes, removes invalid optional catalogue websites, and percent-encodes raw path brackets before URI validation. Remote repositories require HTTPS, optional publisher checksums are enforced, and installed code and metadata are published atomically. Each source owns a serialized QuickJS runtime with evaluation, response-size, and cache limits. Installation initializes the runtime before code becomes active. Android application context enters explicitly through `NovelPluginManager`, `NovelPluginSource`, `NovelPluginRuntime`, and `NovelPluginLibrary`; the runtime never resolves an unregistered raw `Context` from global DI. Browse rows resolve relative plugin icon paths against the trusted repository and load them through the same Coil-backed source image view used by J2K. Source construction and asynchronous warm-up failures remain attached to the current installed plugin ID in the extension catalog instead of disappearing. The bridge exposes only the compatibility APIs needed by LNReader plugins, including network, Cheerio and Jsoup, storage, timers, crypto, URL, and protobuf helpers. It does not expose Android APIs or app lifecycle APIs. `NovelPluginManager` restores a missing trust record for every repository that the user already configured. This repairs repositories migrated from builds that persisted the repository before its trust record. Existing signed trust records remain unchanged.

## Database reset and migration

Legacy Hayai and current J2K both called their database `tachiyomi.db`, but their schema histories are unrelated (legacy SQLDelight v36+ versus J2K StorIO v20). Hayai therefore uses `hayai-j2k.db` as the active J2K database and treats an existing `tachiyomi.db` as a read-only source.

On first database open, an idempotent importer validates the legacy schema and requires the fresh J2K target to be pristine. It imports compatible J2K core rows in dependency order, imports quotes/novel/E-Hentai/search data into typed tables, and also archives every source row with table and row identity in `hayai_legacy_rows`. The raw archive preserves columns J2K cannot represent. Inserts abort on any identity conflict; a non-pristine target is refused rather than silently merged or overwritten. The importer checks foreign keys and records a durable result. The source database is never modified. A failed import rolls back and records a recoverable diagnostic without entering an app-start retry loop. A separate idempotent quote-recovery generation invalidates the superseded quote markers, replays archived `series_quotes` payloads, then restores pre-SQLite quote files from the retained `__APP_STATE_storage_dir` or the legacy `Hayai/quotes/novel_<id>.json` default. It ports both exact shapes from legacy Hayai commit `c1aab40f664dd2eec09774b653535021302f8e86`, never deletes source rows or files, never overwrites an existing typed quote, and does not record completion while storage is inaccessible, a file is unreadable, or a manga identity is absent. Because modern scoped-storage devices can deny the obsolete raw path even when the files remain visible to the system picker, the Saved quotes UI also accepts multiple JSON documents through Android's Storage Access Framework and merges every resolvable novel in one transaction. Manual recovery prefers the preserved numeric ID and falls back only to one exact, case-insensitive novel-title match; absent or ambiguous identities remain rejected.

J2K's existing source-migration screens remain the only migration surface. Their source rows are partitioned by the shared Manga/Novel policy, and the target chooser accepts every discoverable `CatalogueSource`, including local and JavaScript novel sources. The policy does not demote an imported novel when its old source is unavailable: a live novel capability, an exact legacy novel genre, a remembered novel-plugin source ID, or retained quotes, highlights, chapter statistics, or completed translations is sufficient proof. One adapter call invokes Hayai's `NovelMigrationDataMover` inside J2K's existing transaction after target chapters exist; the mover does not open a nested transaction. Before writing, it builds a one-to-one chapter-number map for every chapter carrying selected J2K chapter state or Hayai statistics, highlights, and completed translations and refuses missing or ambiguous mappings. The existing Chapters flag continues to govern J2K read, bookmark, history, `last_page_read`, and `pages_left` state. Hayai quotes, word counts, highlights, and complete translations always transfer with the novel. Completed translations use the mapped local chapter plus stable source, manga URL, chapter URL, and target language; exact target duplicates are idempotent and different target content aborts the caller's transaction. Replace cancels old mutable translation jobs instead of moving provider work across sources. Target-owned rows remain intact. Source metadata, repositories, plugin identity, the legacy archive, and original downloaded documents remain under their original ownership and are not relabelled during migration.

The migration presentation uses `NovelContentIdentity` as the same classifier already consumed by library, details, statistics, and target filtering. Migration rows and flags choose localized manga or novel vocabulary from that identity. `SourceArtwork` supplies one shared icon binding for Browse and migration, while `SourceCoverRequestProvider` lets a JavaScript novel source provide J2K's cover fetcher with the same authenticated client, cookie, and referer it uses for chapter traffic.

Download and backup preferences keep J2K's existing settings and workers, but all location access crosses Hayai's `StorageLocationAccess`. New installations default to app-owned external directories and fall back to internal app storage. User-selected directories retain Android Storage Access Framework write permission, and each use validates that permission and writability before work starts. Raw shared-storage paths remain readable only when Android's all-files permission actually applies. Automatic backup failures use J2K's existing backup notification instead of failing silently. No existing user path is silently moved or rewritten.

Paginated Web layout uses one viewport-wide stride for geometry, seeking, visible-page reporting, and navigation. Offline asset names retain a bounded original extension so WebView can infer CSS, script, font, and image types, while the hash remains the identity. Packaged chapter assets always resolve locally, and unrelated remote custom-style assets remain available when network media is allowed.

## Reader and source architecture

Extensions remain standard J2K `Source`/`SourceFactory` extensions. `SourceCapabilityRegistry` adds behavior by stable source ID or recognized family name instead of scattering source checks through presenters.

The Advanced setting `eh_is_hentai_enabled` controls adult source discovery. When enabled, the main Settings screen exposes a dedicated E-Hentai and ExHentai page; account, browse/detail behavior, batch-add, favorites sync, server settings, and gallery-updater controls do not remain scattered through Advanced. Disabling adult features reactively removes the dedicated settings entry and recognized adult sources from browse, global search, migration, and settings search without unregistering them, deleting data, or making existing library entries unreadable. The independent library filter uses SY's `pref_filter_library_lewd_v2` contract: disabled shows all entries, include shows only lewd entries, and exclude hides lewd entries. Classification includes SY's legacy ID range, complete source-name rules, adult genre tags, and the `Non-H` exception only for E-Hentai, ExHentai, and nHentai families.

`NovelSource` returns one `NovelDocument` per chapter. `ReaderLauncher` centralizes all current direct chapter-launch paths and always opens J2K's `ReaderActivity`. `ChapterLoader` selects a Hayai `NovelChapterPageLoader` only for a source that proves the novel capability; image sources retain J2K's original loaders. Library, recents, notifications, TTS notifications, search, and manga details call this router. Local HTML/text/EPUB sources, downloaded source chapters, installed Tsundoku novel APKs, and explicitly trusted LNReader JavaScript repositories are production implementations.

`SettingsSearchHelper` contains one registration seam for `NovelSettingsController` and conditionally registers `EhSettingsController` while adult features are enabled. Both controllers and their preferences remain under the Hayai namespace. This seam makes the full novel reader and E-Hentai settings searchable without moving their behavior into J2K. Novel language tools, custom-source building, import/export, enhanced batch add, and E-Hentai account controls are J2K `SettingsController` screens. APK and JavaScript extensions are managed only from Browse's Manga and Novels tabs in the J2K Extensions sheet. Their feature state, validation, jobs, and persistence remain owned by their typed backends. Authenticated WebView flows retain dedicated activities; novel reading does not.

`PreferencesHelper` has one compatibility seam that routes its enum-backed FlowPreferences through Hayai's non-throwing name decoder. Current enum names round-trip unchanged, known legacy aliases retain the closest supported behavior, and removed or future values use each preference's declared default without rewriting the stored value. This protects startup, shortcuts, widgets, settings, and presenters before they consume restored pre-reset preferences. The legacy `group_chapters_history_type=BySource` value is a live enum member again and renders History source sections instead of projecting to `BySeries`. The complete reset-era preference comparison is recorded in `docs/development/legacy-preference-audit.md`.

Browse and Recents share J2K's activity-owned tab strip. Their controller exit callbacks must not hide or clear that strip when the destination implements J2K's `TabbedInterface`; the entering controller remains responsible for replacing the tab contents. This keeps tab ownership inside existing J2K controller lifecycle and avoids changes to `MainActivity`.

The Library toolbar exposes an always-visible All/Manga/Novels selector backed by `NovelLibraryFilter`. It changes only the existing J2K library query projection; manga and novels remain in one authoritative library and no parallel category, favorite, or progress model is introduced.

Novel title wrapping is an approved library-presentation seam. The existing J2K grid and list holders ask `NovelTitlePresentation` for a one-to-five line limit only when durable content identity says the row is a novel. Manga keeps J2K's two-line behavior, and an author search still reserves a line for its matching subtitle. The preference lives in J2K's existing Library settings page and normal preference backup; no alternate library card or settings screen exists.

J2K's `ReaderActivity` owns the text reader lifecycle as well as the image reader lifecycle. For a proven novel source it installs one Hayai `BaseViewer` and one attachment behind J2K's existing toolbar, navigation overlay, slider, chapter sheet, key handling, adjacent-chapter controls, progress writer, history, and tracking. `NovelChapterPageLoader` exposes 101 ready progress pages as a normalized 0–100 adapter; these pages never enter J2K image holders. The default text viewport is a native selectable renderer. Web rendering remains isolated, blocks unsafe navigation and file access, and supports independent continuous/paginated layout plus horizontal/vertical-rl writing direction. The seven J2K/Tsundoku tap-zone modes share their stored keys. Hayai does not own a second reader activity, chapter index, chapter adapter, or progress writer.

Read-aloud state lives in a Hayai foreground media-playback service rather than the activity. The notification exposes play, pause, stop, and paragraph navigation, and returns to the same J2K reader through `ReaderLauncher`. `NovelReaderAttachment` hosts quotes, highlights, translation, dictionary/search handoff, statistics, offline actions, editing, fonts, orientation, and reader settings in J2K's existing action surfaces. Native and Web renderers keep the typed selection contract. Paginated Web rendering reports real page number/count to J2K while persisting normalized percent progress; vertical Japanese uses `writing-mode: vertical-rl` and `text-orientation: mixed`. Translation providers, visual custom-source compilation, presets, snippets, and EPUB export remain Hayai-owned and do not change image-source behavior. Emulator verification remains required before this implementation becomes a verified port.

Novel integration uses a small set of adapters rather than parallel J2K models. The library filter delegates content-kind classification to Hayai. Manga details decorate the existing chapter rows with percent, word count, reading time, and verified offline state. Novel chapter downloads enter J2K's `DownloadQueue`, `DownloadJob`, status flow, notification, details actions, reader action, and Downloads sheet. `NovelDownloadQueueSource` supplies the queue-only `HttpSource` shape that J2K's `Download` model requires. The adapter retains the real source ID, name, language, novel marker, and metered policy. No HTTP operation runs through the adapter. `Downloader` calls `NovelDownloadDelegate` only to check and save a novel chapter in Hayai's document store. Immediately before that save, one Hayai `NovelDownloadThrottle` call applies a cancellable per-source delay using a global default and stable source-ID overrides; `UnmeteredSource` implementations bypass it, and manga downloads, browsing, reader requests, and library updates never enter it. `DownloadStore` reconstructs the same adapter after process restart, and `Downloader` drops a restored item when the atomic novel document already exists. An explicit `autoStart` request starts a stopped non-empty queue as well as an empty queue, so one restored novel item cannot make later manga downloads emit an immediate permanent pause. Manual queueing still preserves a deliberate pause. The details adapter preserves J2K's active `QUEUE`, `DOWNLOADING`, and `ERROR` states when it refreshes offline novel metadata. The normal queue listener marks the offline row before J2K removes a successful queue item. Image sources continue through J2K's original directory and page path without an adapter. Novel removal deletes the Hayai document and refreshes the same details row. J2K statistics aggregate Hayai's derived word data, shortcuts preserve novel identity, and migration searches reject novel-to-image and image-to-novel targets. `NovelSettingsController` owns the complete text-reader preference surface, typed reusable presets, CSS and JavaScript snippets, and bounded text-replacement rules. Translation, dictionary, and visual-source-builder settings use J2K `SettingsController` screens and preference rows while their drafts, validation, network preview, and persistence remain Hayai-owned. J2K remains authoritative for chapters, download scheduling, progress, history, categories, and the enclosing screens.

The novel reader is J2K's existing `ReaderActivity`; it does not independently inflate or bind `reader_activity`. The real app bar, toolbar, viewer container, navigation controls, chapter sheet, slider, insets, lifecycle, and gestures therefore remain shared by construction. `ReaderActivity` has three narrow Hayai adapter points: select/close the novel attachment and viewer, present percentage or renderer-reported page counts, and let novel actions populate existing menu/button slots. `ReaderViewModel` has one typed novel-progress branch; its image page and double-page branch is unchanged.

Hayai branding is resource-owned: the Android splash animates the existing Hayai vector and product-identity notifications use the Hayai monochrome vector. Download, warning, TTS, and extension notifications keep their semantic J2K status icons.

Custom application color is a Hayai-owned content-seed preference and picker hosted in J2K's Appearance settings. Both J2K base activity families make one pre-inflation call to the Hayai applicator after selecting the base theme. Material's runtime color resources generate the scheme when the device supports them; unsupported devices expose a disabled setting with an explanatory summary and leave the selected J2K theme unchanged. J2K's later AMOLED overlay remains authoritative.

Source-specific details use independent generic metadata and preview provider registries on manga details. E-Hentai, NHentai, and LANraragi providers return typed paginated preview metadata with globally stable image indices; E-Hentai and each enhanced-source family return typed metadata documents. Images and sprite regions are fetched lazily through the source's authenticated client, bounded on disk and during decoding, and released when the view is rebound. The E-Hentai parser follows SY's sprite-first precedence for legacy `.gdtm`/`.gdtl` and current direct-anchor layouts, including unitless zero offsets, and rejects nested `blank.gif` placeholders as real previews. Listing-cache schema changes invalidate stale successful-empty, blank, or incorrectly paged listings, and cache publication cannot suppress a successful network image. Preview requests remove E-Hentai's one-shot `nw=always` query before adding `p=N`; retaining both parameters makes the server redirect every listing back to preview page zero. E-Hentai maps typed metadata to the SY-style metadata block only; it no longer duplicates the same fields in J2K description text. Both phone and tablet manga-header layouts expose two independent anchors: structured metadata before the generic description and page previews after tags/description. Inline and full preview surfaces port SY commit `14648c7cf0aa84e5a35d48de9dbf1386df6cca42` geometry: 120 by 200 dp width-filled thumbnails, small clipping, width-derived rows, 8 dp outer/row spacing, and 16 dp column spacing. The full page uses SY's single direct-page slider action; selecting a page reloads the authenticated listing and resets scroll before preview taps route through `ReaderLauncher` to the existing J2K reader at the selected image. No source parser, cookie rule, metadata field, or bitmap-cropping branch lives in the J2K controller.

The browse-source presenter and its existing holders form one approved presentation seam for E-Hentai's SY-style result metadata. The presenter asks a source for an optional immutable `SourceBrowsePresentation`. SY's `enhanced_e_hentai_view` preference explicitly selects the 148 dp detailed list; the normal J2K display action switches that preference and J2K's own list/grid preference together, so it can always leave the enhanced list for a real image grid. Detailed rows render uploader, rating, category, language, page count, and date. Grid cards keep J2K's cover behavior and add compact category and language badges from the same typed presentation without another network request. Language prefers source metadata and tags, then conservatively recognizes Japanese kana, Korean Hangul, or Han-only titles when the selected server browse layout omits tag metadata; ambiguous Latin titles stay unbadged. Parsing, category colors, localization, caching, and source-family recognition remain under `dev.ahmedmohamed.hayai`. Normal sources still take the original grid/list paths without extra work. The same presenter has one generic typed-filter branch for Hayai tag completion, while the E-Hentai catalog, chip state, validation, and suggestions remain Hayai-owned.

Built-in source settings are another deliberate adapter seam. `BrowseSourceController` pushes E-Hentai sources into the Hayai account `SettingsController` inside J2K navigation and sends other built-in `ConfigurableSource` implementations to `SourceSettingsController`. This fixes JavaScript novel source settings without adding a second settings model or activity shell. Extension sources continue to use `ExtensionDetailsController`.

Saved source searches are an approved filter-sheet seam. One action on J2K's existing `SourceFilterSheet` stores the current query and recursively typed filter values through `SavedSourceSearchStore`. Restoring starts from the source's current filter schema and applies only structurally compatible values, so an extension update cannot replay an invalid select or sort index. The data is a bounded Hayai preference and therefore travels through J2K's existing preference backup rather than a second backup pipeline.

J2K's extension-facing `JavaScriptEngine` delegates evaluation to Hayai's QuickJS runtime. The novel plugin bridge needs the Dokar binding API, while J2K previously packaged a second QuickJS implementation with the same native `libquickjs.so` name. One Hayai-owned evaluator preserves the extension API and prevents an unresolvable APK native-library collision without changing application lifecycle code.

The Cloudflare interceptor and WebView help behavior follow Mihon commit `ac249e3668a57f24782a49218834064459ba2d09`. The interceptor detects the official `cf-mitigated: challenge` response header and stops the bypass when Cloudflare reports an interactive challenge. After a WebView page finishes, the adapter checks Mihon's `window._cf_chl_opt` and `Ray ID is` markers and exposes the same tappable error banner linked to Mihon's Cloudflare troubleshooting guide. The default HTTP and WebView identity is the requested Chrome 151 Android mobile user agent; custom stored user agents remain authoritative. Hayai keeps J2K's client, cookie jar, and source-header path unchanged.

Source badges and bundled icons use Hayai-owned presentation resolvers. The browse list and both migration lists render only facts that the live source proves: `Bundled`, `JS`, `Novel`, and `Adult`. The resolver does not label an enhanced-source family until its delegated behavior exists. The J2K `Source.icon()` seam asks Injekt for the registered `Application`, not an unregistered raw `Context`, before resolving a bundled fallback. This keeps the badge UI honest and source rows safe while limiting J2K changes to presentation holders and one icon fallback.

Hayai-owned interface text uses `hayai_` Android resources. Pure parsers and services return typed labels or failure reasons when their output reaches the interface. Android-aware adapters resolve those types without translating source titles, protocol values, selectors, URLs, or server data. J2K presentation seams receive a `Context` only when they render a Hayai badge. `tools/verify-localization.ps1` rejects new interface literals, validates resource placeholders, and records reviewed nonlocalizable literals separately from the pinned J2K exception list.

Release channels use a Hayai-owned policy. Stable and beta builds query `HayaiApp/hayai`. Nightly builds use the isolated `.nightly` application ID, numeric `rN` versions, and `HayaiApp/hayai-nightly`. J2K's update checker delegates tag comparison and APK selection to this policy. The nightly workflow chooses `max(commit count, latest published nightly + 1)`, which prevents version rollback after the J2K reset and remains safe when a canceled job retries.

Inherited About and HTTP client identity links are an approved branding seam. Product navigation points to `HayaiApp/hayai`, its wiki, and its channel-specific releases. Upstream J2K, SY, Tsundoku, LNReader, Mihon, and legacy links remain only where they document provenance, licensing, behavior references, or still-applicable upstream help. Hayai does not invent social accounts or redirect users to unrelated issue trackers.

The minified build keeps Hayai-owned classes under the same release boundary as J2K-owned classes. Its R8 configuration preserves generic signatures and Injekt `TypeReference` subclasses because Injekt resolves reified Kotlin registrations from that runtime type metadata. It also preserves Hayai serializers and companion factories. The nightly workflow signs the x86_64 APK, launches that exact minified artifact on an Android 12 emulator, rejects any startup fatal exception or crash-handler redirect, and only then prepares and publishes release assets. This is an intentional J2K build-file seam: a new namespace cannot safely inherit rules scoped only to `eu.kanade`.

`master` is the active J2K reset branch. The previous application remains on `legacy/hayai-pre-j2k` for migration evidence. Release procedures live in `docs/development/releases.md`.

Enhanced extension sources pass through `EnhancedSourceRegistry` during J2K source registration. A matching wrapper keeps the extension source ID and delegates filters, settings, browse pages, chapters, pages, images, normal URLs, cookies, and headers to the installed extension. Hayai adds the source-specific behavior SY exposes for 8Muses, HBrowse, Pururin, NHentai, and LANraragi. This includes host-validated URL import where supported, richer descriptions, generic batch add for importable sources, NHentai previews, and authenticated LANraragi previews. MangaDex-specific recommendations, related titles, and follows are outside this requested slice. A secondary parser failure returns the extension result and never removes a usable source.

E-Hentai preferences retain SY keys and affect the source directly. Japanese-title selection changes `SManga.title`, watched-list and category choices initialize each fresh filter sheet, and SY's enhanced-view key controls the detailed browse list. Hayai's independent enhanced-details key controls structured gallery metadata and page previews, so turning on a grid does not remove preview support. Malformed category and language strings fall back to safe defaults. Remote uconfig uses a Hayai-owned typed settings model and an idempotent per-site profile upsert. It reuses Hayai and legacy SY application profiles, creates only in slots 1 through 3, commits cookies and the selected slot only after a verified apply, and reports partial two-site results for targeted retry. The Hayai settings controller exposes the complete matrix and updater controls through native J2K preference rows and dialogs.

Favorites synchronization uses a persisted three-way plan over the last completed Hayai snapshot, current J2K library state, and a bounded ExHentai snapshot. Remote mutations are journaled and executed before local mutations, use expected preconditions, preserve existing favorite notes during category moves, and verify their postconditions. Local favorite and category changes remain J2K-owned and transition the journal in the same database transaction. Ten explicit slot-to-category mappings prevent remote positions from renaming arbitrary J2K categories, while unrelated categories are retained. Alias components are canonicalized before comparison, ambiguous duplicates and multiple mapped categories become review conflicts, cancellation leaves an active resumable run, and the final remote fingerprint is verified before atomically advancing the baseline and checkpoint.

The gallery updater uses unique WorkManager jobs with connected, unmetered, and charging constraints from user settings. It checks bounded batches, persists freshness, aged, and failure state, and classifies transient failures for retry. Revision merging keeps J2K manga, chapters, history, categories, favorites, and downloads authoritative. A durable download journal stages and verifies file moves before the matching database transaction, so cancellation and process death converge safely on retry.

Novel tracking uses three Hayai-owned services registered through the existing J2K `TrackManager` and tracking settings screen. Manga details asks the manager for services appropriate to the current source, which keeps the novel-only services out of image-manga tracking without adding a second track model. The services own their remote authentication and protocol boundaries, while J2K continues to own manga-track rows, progress updates, status display, and automatic reader-driven tracking.

Recents source visibility uses one Hayai-owned policy seam. History and Updates retain independent
sets under the legacy Hayai preference keys; Grouped and All derive the union. The presenter takes
one immutable source-ID snapshot per loaded page before it groups or decorates rows. The options
sheet delegates source discovery and editing to Hayai, including installed sources, sources still
referenced by J2K manga rows, and unavailable sources that were hidden previously. This is strictly
a presentation filter: J2K remains authoritative for every manga, chapter, history, and update row,
and pagination advances over hidden rows so a page containing only hidden sources cannot loop.
History `BySource` is an approved Recents presentation adapter. `RecentsPresenter` still loads J2K
history rows, chapter expansion, download state, swipe actions, and reader routing. Hayai's
`RecentSourceGrouper` owns only source-section ordering. The existing J2K
`RecentMangaHeaderItem` renders source sections with `SourceManager.getOrStub`, `Source.icon()`,
local source artwork, and a normal J2K popup action to add the section source to the same
`RecentSourceVisibility` policy. No parallel source-header layout is introduced.

## Backup ownership

J2K continues to own backup of library, chapter, category, history, tracking, and selected preferences. Hayai appends a versioned optional protobuf payload for quotes, novel repositories, installed novel plugin code and settings, chapter word counts, highlights, completed novel translations, visual custom-source definitions, tagged novel APK repository URLs, and E-Hentai state. References to J2K rows use `(sourceId, mangaUrl, chapterUrl)` rather than transient database IDs and are resolved only after core restore. Completed translations are bounded, restored only after their chapter identity resolves, and conflict rather than silently replacing different content. Translation jobs, leases, provider configuration hashes, errors, API keys, and credentials are excluded. Quote ID collisions are deterministically remapped from the complete quote payload, and highlight identity conflicts are rejected while mutable color, note, and timestamps converge. Plugin and custom-source code is revalidated through the same installer before publication. Repository signing trust, tracker credentials, import completion markers, and downloaded files are excluded.

Offline novel files are deliberately excluded, matching J2K's treatment of downloaded image pages: backup contains durable user data and state, not potentially large downloaded content.

## Updating upstreams

```powershell
git fetch j2k sy tsundoku
git rebase j2k/master
.\tools\verify-upstream-boundary.ps1
```

TachiyomiSY and Tsundoku are feature references, not architectural parents. Ports are rebuilt behind Hayai contracts with provenance recorded in the feature audit.
